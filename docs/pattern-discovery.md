# Pattern discovery

The bundled engine builds retrospective associations and similar-history summaries from one person's recorded history. The participant app currently keeps pattern cards disabled. The implementation is in [personal_context_engine.py](../src/insite_analytics/personal_context_engine.py), with numeric rule proposals in [numeric_search.py](../src/insite_analytics/numeric_search.py) and default settings in [daily_brief.py](../src/insite_analytics/daily_brief.py).

## Features and target rows

For each historical or current anchor, the shared feature builder uses only records completed and known by that time under the default strict as-of mode. It summarizes glucose over the preceding 1, 3, 6, and 24 hours; carbohydrates and delivered bolus over 3, 6, and 24 hours; and exercise, steps, heart rate, sleep, HRV, temperature, mood, cycle/flow/cramp, and infusion-site context. Several inputs compare the recent seven days with the preceding 28 days. Missing or incomplete values remain unknown, and the numeric matcher excludes a row when a rule needs an unavailable feature.

The engine makes distinct rows for different questions:

- Meal episodes compare later glucose change over 0–3 and 3–6 hours with the mean from the preceding 30 minutes; meal-variance targets cover 3 and 24 hours. A separate pre-meal target summarizes the preceding three hours. Delivered-bolus episodes use actual recorded delivery, with corresponding 0–3 and 3–6 hour outcomes. Correction-only outcomes require an explicit correction-only classification. Fasting rows require an interval with positive fasting provenance.
- Daily-context rows anchor at the same local time on earlier days and measure overnight or 24-hour glucose change and 24-hour variance.
- Clock analyses compare recurring local windows of two, three, or four hours on mean-glucose, time-in-range, observed-low-fraction, and observed-high-fraction targets. Event rows also include fixed three-hour local-clock bins with glucose-change and variance targets.

Target windows must finish before the analysis cutoff. For event and daily searches, rows in the discovery period whose outcomes cross into confirmation are removed. Current-context matching reuses the historical daily feature builder, then applies confirmed daily rules to current as-of values. A separate analogue search retrieves earlier contexts and summarizes their observed later glucose. Neither branch estimates a treatment effect or forecasts an individual's future.

The fasting target requires explicit interval provenance, which current production inputs do not provide; correction-only bolus targets also depend on an explicit classification.

## Search, adjustment, and evidence

The numeric event and daily branches use `pysubgroup.BeamSearch`; the local defaults are depth 4, six discovery-fitted quantile bins for continuous features, beam width 256, and a 128-rule shortlist in each direction. The native proposal minimum-support threshold is three rows; later matching requires six units per arm. Low-cardinality values use equality selectors. A unique-feature constraint limits conjunctions, and missing values are not treated as comparator negatives. This is a bounded heuristic search and can miss rules outside the beam. The clock branch enumerates configured local-time windows rather than using the numeric beam. See the [BeamSearch API](https://pysubgroup.readthedocs.io/en/stable/api/pysubgroup.html).

Event and daily numeric searches use the earlier 60% of eligible dates for discovery and later dates for confirmation; discovery outcomes that cross the first confirmation anchor are purged. The clock branch also separates discovery and confirmation by date. Feature cutpoints and the nuisance ridge are fitted on discovery rows only. The ridge adjusts for starting glucose, preceding glucose trend, and local time, with recorded carbohydrate and bolus terms when available and allowed by the target. For delivered-bolus-response targets, the bolus remains the exposure and is not adjusted away; carbohydrate history remains available for adjustment. Matched pairs compare different dates with similar starting glucose, trend, and recorded carbohydrate availability/amount; bolus availability/amount is also matched when bolus is a nuisance variable. When both rows carry a therapy-profile fingerprint, it must match. Later meals and boluses remain co-exposures.

The default requires six matched units per arm. Up to six candidates across clock, event, and daily branches enter one frozen confirmation family. Support requires the direction to agree with discovery, a minimum effect, stable direction when each confirmation day is omitted in turn, and an approximate contiguous-day block-bootstrap interval excluding zero. The default interval uses two-day blocks and 10,000 draws with a Bonferroni adjustment across that global family. These intervals are approximate; repeated later snapshots are not anytime-valid. If support is insufficient, the engine can return no finding.

Each released item links to structured evidence: comparison outcome and horizon, support, matched method, an interval, and representative recorded episodes. The engine marks these results retrospective and noncausal. The [app and privacy notes](app-and-privacy.md) describe the disabled participant surface. The saved [synthetic example](../examples/README.md) includes wording accepted in an earlier offline local-model pass; the model runtime and weights are not bundled, and a fresh demo run does not call a language model.
